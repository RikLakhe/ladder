# Feedback, Communication & Collaboration — Learning Path

Reads: `../functional-analysis.md`, `../standard/` (all 3 PFs — read-only, not edited by this package), `../assessment/` (all 3 PFs' rubric/checklist/portfolio files, plus `00-evidence-bundle-standard.md` and `badges.md` — the 18-badge catalog, redesigned 2026-08-03, this training package is built to prepare candidates for), `../../industry-evidence/feedback-communication-collaboration.md`, `../../COMPANY-CONTEXT.md`.

**Level scope of this run:** whole P2–P7 ladder is covered structurally (all three PFs run P2–P7 per `functional-analysis.md`), but the guided exercises and autonomous projects — the parts of this kit that are actually buildable as step-by-step content — are scoped to **P2–P4**, matching where the assessment package provides a concrete rubric/checklist target (the dated evidence bundle) to train toward, rather than a portfolio review. P5–P7 readiness is demonstrated through real team/cross-team/org-wide culture-fostering work and portfolio review per each PF's `03-portfolio-requirements.md`, not through guided exercises — see the Level gates section below and `03-autonomous-projects.md`'s framing. This is the "P5–P7 growth is demonstrated through real scope, not guided exercises" principle the methodology names generally (`competency-methodology.md`, "Level Scoping"), applied here rather than assumed.

See `05-badge-reference-card.md` for a one-screen map of every badge in `../assessment/badges.md` to the training unit that builds its evidence artifact.

**What changed in the 2026-08-03 assessment redesign, and why it reshapes this training package:**
- All three PFs' P2–P4 evidence is no longer "bring 2–3 best examples" — every rubric now requires a **dated evidence bundle spanning a real 4–6 week working window**, logged as you go (`../assessment/00-evidence-bundle-standard.md`). Every guided exercise below is rebuilt to seed and extend that bundle, not to produce a disposable one-off artifact.
- PF3 P4 now requires a **multi-engagement boundary-keeping** instance (if staffed on ≥2 concurrent client engagements) — Exercise 4 below is built specifically to produce this.
- PF3 P5 now requires evidence of **coaching a named teammate** on client-team structure or multi-engagement collaboration, distinct from the candidate's own adaptation — flagged explicitly in Autonomous Project 3 and the P4→P5 gate below, since this can't be faked from self-modeling.
- PF2 P2 promotes the **async cross-timezone handoff note** to a required, non-optional bundle item (not something only client-facing engineers need) — Exercise 3 below is built around it. Exercise 3 is also extended (step 5) to reach PF2 P4's ≥2 dated client-ready communications and bad-news/escalation instance.
- PF1 P5 now has a dedicated real training unit — Autonomous Project 4 below — producing feedback-culture-adoption and matrixed-feedback-coaching evidence matched to PF1's own P5 portfolio rows, rather than borrowing PF2's norm-adoption project.
- Every guided exercise and autonomous project below now states which badge(s) it feeds and which instrument will actually score the resulting artifact — training builds the evidence bundle; it does not award the badge (see `badges.md` §1.3).

## Prerequisites checklist

Before starting this learning path, confirm:

- [ ] Has been on the team long enough to have at least one real feedback exchange, one written communication sample, and one collaboration instance to log — this path assumes real work exists to draw from, not a simulated backlog
- [ ] Has read `../../lft-engineering-competency-matrix.md` Section 3 "Feedback, Communication & Collaboration," so the P2–P7 language here isn't unfamiliar
- [ ] Has skimmed `../assessment/badges.md` Part 1 (the generic badge pattern) and Part 2's table for their target level, so they know what evidence they're accumulating from day one
- [ ] Access to the team's documentation platform, on-call tooling (if applicable), standard feedback/retro channels, and whatever async status channel is used for cross-timezone handoffs
- [ ] If on a client engagement: knows who their client-side counterpart(s) are, what the escalation path to the client is, whether their reporting structure is matrixed (client stakeholder directs day-to-day work; LFT lead/manager holds the formal feedback record), and whether they are single- or multi-staffed across concurrent engagements
- [ ] Understands the **bundle** vocabulary before starting: a dated evidence bundle (per `../assessment/00-evidence-bundle-standard.md`) is a real 4–6 week working window, logged with one-line dated entries as events happen — not reconstructed from memory the night before a review. Pick the window *before* starting the exercises below.

## Level gates

- **P2 → P3:** the candidate's dated bundles across all three PFs pass their respective `01-work-product-review-rubric.md` at "Meets P3," and the structured conversations (`02-live-demo-checklist.md` in each `pf*/` folder) pass at P3. Badges typically cleared at this gate: FCC-1-P3, FCC-2-P3, FCC-3-P3. Gate owner: candidate's manager or a P4+ engineer, reviewing the real bundle directly, not a summary of it.
- **P3 → P4:** passes "Meets P4" on all three rubrics, including PF1's outside-immediate-team feedback instance, PF2's ≥2 dated client-ready communications and bad-news/escalation instance, and PF3's proactive-help and (where applicable) multi-engagement boundary-keeping instances. At this tier, FCC-1-P4, FCC-2-P4, and FCC-3-P4 all require the candidate's delivery/account manager as **co-signer** per `badges.md` §1.1 — flag this early so the co-signer isn't a last-minute scramble. If a required instance is genuinely inapplicable (no matrixed engagement, no client contact, single-staffed), it's marked N/A per `badges.md` §1.7, not treated as a gap.
- **P4 → P5:** scope-of-role transition (execution → culture-fostering) — not producible by a guided exercise. Gate is the Phase D portfolio requirements for P5 across all three PFs (`pf1.../03-portfolio-requirements.md`, `pf2.../03-portfolio-requirements.md`, `pf3.../03-portfolio-requirements.md`), using real on-the-job evidence, plus — for PF1 specifically, a named instance of a teammate adopting feedback-giving/feedback-seeking behavior and a documented matrixed-feedback-reconciliation coaching instance, and for PF3, a named, corroborated instance of coaching a teammate on client-structure or multi-engagement collaboration (neither satisfied by the candidate's own adaptation restated as coaching/culture-fostering). Autonomous Projects 2, 3, and 4 are reasonable on-ramps, not substitutes for the portfolio review.
- **P5 → P6 → P7:** same pattern, scaling scope from team to several teams to organization, with the §1.6 adoption-evidence artifact (named contact, dated reference, what changed) required for any P6/P7 badge whose Certifies line depends on adoption, and the §1.1 co-signer requirement applying again at Tier 5 (P6). See each PF's `03-portfolio-requirements.md` — there is no further guided/autonomous content at this scale in this run; readiness is demonstrated through actual cross-team/org-wide culture-fostering work, assessed via portfolio + (at P7) a teaching/culture demonstration.

## Levels built out this run vs. deferred

**Built out this run (P2–P4):** concept notes (unchanged in scope — theory doesn't level-gate, so §1–11 cover concepts relevant through P5's culture-fostering mechanics), guided exercises (1–5) and Autonomous Project 1 all target P2–P4 explicitly, rebuilt to produce the exact dated bundle the redesigned rubrics require, each labeled with the badge(s) it feeds — including Exercise 3's step 5 extension, which is the real training unit for PF2 P4 (FCC-2-P4), and Exercise 4's step 2, which is the real business-stakeholder relationship instance Exercise 5 (PF1 P4) depends on. Autonomous Projects 2, 3, and 4 reach into P5 deliberately as stretch on-ramps, since PF1/PF2/PF3's P5 portfolio rows (feedback-culture adoption and matrixed-feedback coaching; norm-adoption; coaching-on-client-structure) are learnable-in-principle even though the badge itself needs real cross-team/portfolio evidence.

**Deferred this run (P6–P7):** no new guided/autonomous content was built for P6/P7. This is a deliberate, stated deferral, not a silent gap — at P6/P7 all three PFs' portfolio requirements call for real cross-team/org-wide culture-fostering plus (at P7) a teaching demonstration, which by definition isn't something a guided exercise can simulate meaningfully. What P6/P7 candidates need from this training package is already present: the onboarding-track pattern, the concept notes (which don't level-gate), and the badge reference card's pointer to the correct portfolio-requirements file per PF. A future training run could add P6/P7-specific facilitation content if the theme lead decides that's worth building despite the real-work bias — not done here.

## Skip guide

- **Experienced hire joining at P4 or above:** skip concept notes and guided exercises entirely. Start at Autonomous Project 1 (to establish a real bundle in the new environment quickly) or, if already past P4, Project 2/3/4. Check `05-badge-reference-card.md` first to see which badges their existing evidence might already satisfy.
- **Experienced hire joining at P3:** skim concept notes as a refresher, go straight to Exercises 1–3 to build a real LFT-dated bundle (prior-company evidence in a different tracking system isn't reviewable and needs to be rebuilt), then proceed to Exercise 4/5 (in that order — see the ordering note above) and the autonomous projects.
- **Anyone who has held a lead/mentor-adjacent role before:** skip the concept notes' basic feedback/communication framing, but still build real dated bundles (Exercises 1–3) — LFT-specific matrixed-feedback, cross-timezone, and multi-engagement realities won't transfer automatically from a prior company.
- **Anyone new to services/consulting delivery (even if experienced at a product company):** do not skip Exercise 3's cross-timezone handoff item, Exercise 5's matrixed-feedback reconciliation, or Exercise 4's multi-engagement boundary-keeping, regardless of level or tenure — these are LFT-specific realities that don't transfer from a product-company background, where the manager and the day-to-day work-director are usually the same person and multi-client staffing doesn't exist.
