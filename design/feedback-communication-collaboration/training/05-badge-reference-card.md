# Feedback, Communication & Collaboration — Badge Reference Card

**Purpose:** a one-screen lookup so a candidate or buddy can see, at a glance, which training unit prepares which badge — without re-reading all nine assessment instruments across the three PFs. This card does not redefine anything; every cell links back to `../assessment/badges.md` and the instrument it names. If this card and an assessment instrument ever disagree, the instrument in `../assessment/` wins.

**Reuse note (for future competencies):** this file's *shape* — one row per badge, linking training unit → evidence artifact → instrument — is the reusable pattern, copied from Technical Skill's and Delivery's `05-badge-reference-card.md`. Only the PF names, badge IDs, and artifact names are specific to this competency.

---

## How to read this card

- **Badge ID** and **Name** — from `../assessment/badges.md` Part 2.
- **Training unit that builds it** — which guided exercise, autonomous project, or onboarding milestone in this `training/` folder produces (or extends) the required evidence artifact.
- **Evidence artifact required** — restated from the badge's "Evidence required" field, so you know what to walk away from the training unit holding. Where the artifact is a **dated 4–6 week bundle** (P2–P4, all three PFs), this reflects the 2026-08-03 redesign — a hand-picked "2–3 best examples" set no longer qualifies.
- **Instrument** — which file in `../assessment/` actually awards the badge.

Training builds the artifact. It does not award the badge — only a Verifier at the role/level named in the instrument can do that (see `../assessment/badges.md` §1.3), including the required co-signer at Tier 3 (P4) and Tier 5 (P6) per §1.1.

**Note on Exercise 4/5 numbering:** in `02-guided-exercises.md`, Exercise 4 (PF3, multi-engagement boundary-keeping) is sequenced before Exercise 5 (PF1, matrixed feedback) because Exercise 4 step 2 builds the business-stakeholder relationship Exercise 5 depends on — the exercise numbers don't match PF1-then-PF3 reading order in this one case.

## Bundle requirements this card assumes (2026-08-03 redesign)

- **All three PFs, P2–P4:** the evidence bundle must span **one real, continuous 4–6 week working window**, chosen and logged as-you-go before it starts — not a hand-picked set of "2–3 best examples" from anywhere in the candidate's career. Pick the window before starting, per `02-guided-exercises.md`'s "Before starting any exercise" note.
- **At least one instance across the bundle must involve someone outside the candidate's closest working pair** (a different teammate, a client stakeholder, a cross-timezone counterpart) where the standard calls for a widening audience at that level — per `00-evidence-bundle-standard.md` §2. Check this explicitly around the 3-week mark; don't discover the gap at review time.
- **PF3 P4's multi-engagement boundary-keeping row** and **PF3 P5's coaching-on-client-structure row** are both N/A (not failing) for candidates who are single-staffed or haven't yet coached anyone — see `badges.md` §1.7. Do not manufacture a scenario to fill either row.
- **PF2 P2's async cross-timezone handoff note** is required regardless of level, client contact, or staffing — it is not gated by any N/A exception, since the timezone gap applies to internal cross-region teammates too.
- Neither the bundle window nor the widening-audience instance can be manufactured retroactively. If a candidate discovers mid-review that their evidence spans the wrong shape (scattered instances, a broken window, everything with one person), the fix is to run the training unit again against a real, freshly-started window — not to reconstruct one from memory.

## What this card is not

- Not a substitute for reading the actual rubric/checklist/portfolio file before an assessment — it tells you where to look, not what the bar is in full.
- Not a self-certification tool — see `../assessment/badges.md` §1.3: a badge requires a named Verifier's sign-off, always, plus the co-signer at Tier 3/Tier 5 where noted above.
