# Feedback, Communication & Collaboration — Onboarding Track

For a new hire (or an existing engineer newly picking up this competency) who needs to get up to speed fast.

**Badge context:** by the end of Month 1, a P2 new hire should be partway through a real 4–6 week dated bundle across all three PFs (`00-evidence-bundle-standard.md`) — the evidence FCC-1-P2, FCC-2-P2, and FCC-3-P2 all require. None of this can be assembled retroactively at review time; see `05-badge-reference-card.md`. None of this is awarded automatically by finishing the track — a Verifier still reviews the real artifacts produced along the way, per `../assessment/badges.md` §1.3.

## Day 1

**Read:**
- `../../lft-engineering-competency-matrix.md` Section 3 "Feedback, Communication & Collaboration" — the source of truth this competency is built from
- Concept notes §1–2 and §7 (`01-concept-notes.md`) — what makes feedback useful, seeking feedback as a habit, and psychological safety/healthy disagreement
- `../../COMPANY-CONTEXT.md` — the distributed Nepal/India–US structure that shapes the cross-timezone and matrixed-feedback realities this competency covers
- `05-badge-reference-card.md` — skim once so the new hire sees what "done" eventually looks like (a real dated bundle), without needing to read every assessment instrument on Day 1

**Do:** get access to the team's feedback/retro channels, documentation platform, and whatever async status tool is used for handoffs. Confirm who their onboarding buddy is; find out which client engagement (if any) they're joining, whether their reporting structure is matrixed (client directs day-to-day, LFT manager owns the formal record), and whether they're single- or multi-staffed. If a bundle instance will ever need to reference client-confidential material, flag now that the `../assessment/badges.md` §1.5 in-place attestation path exists as a fallback.

**Set the bundle clock now, not later:** identify, on Day 1, the real 4–6 week window that will become the Exercise 1–5 evidence bundle across all three PFs. Start the one-line dated log today — don't let this drift into "whichever examples look good in retrospect."

## Week 1

**Do:**
- Start Guided Exercise 1 (feedback bundle) on the first real feedback-worthy moment that comes up — a PR comment, a demo, a 1:1 — logging it the same day
- Start Guided Exercise 2 (collaboration bundle) on the first real helping/credit/relationship/disagreement instance — these tend to happen naturally in week 1 of any team, so the buddy should point them out if the new hire doesn't notice them as bundle-worthy yet
- Start Guided Exercise 3 (communication bundle), specifically identifying the first moment a cross-timezone async handoff will be needed — this is a P2 requirement from day one, not something to defer until client-facing work starts

**Read:** concept notes §4–6 and §8–9 (audience-oriented communication, knowledge sharing, async writing, relationship-building, working inside a client's structure) alongside starting Exercises 2–3.

## Month 1

**Deliver:**
- Continue logging into the same bundle throughout the month — by week 4, the bundle should have ≥2 feedback-given instances, 1 feedback-sought instance, an audience-aware sample, a knowledge-sharing instance, a documentation contribution, a cross-timezone async handoff note, and the full set of P2 collaboration instances (help, credit, relationship, disagreement-resolved, mind-changed)
- Check at the 3-week mark whether the bundle naturally covers someone outside the new hire's closest working pair (per `00-evidence-bundle-standard.md` §2) — if everything so far is with the same one or two people, deliberately seek an instance with someone else before the window closes
- If client-facing: complete the client-structure-adaptation instance (Exercise 2, PF3) and, if applicable, a calibrated client-facing communication artifact (Exercise 3, PF2)
- Have the bundle ready — dated, logged, not reconstructed — for a first informal review with the buddy or manager before the formal P2 rubric session

**Read:** remaining concept notes (§3, §6a, §9a, §10–11) as the relevant exercises or real situations come up, rather than all at once — §9a (multi-engagement boundary-keeping) and §10 (matrixed feedback) only become relevant once the new hire is actually staffed that way.

## Buddy check — 2-week check-in questions

- "Show me your bundle log so far — is every entry dated, and does the date match when it actually happened, not when you're writing it down today?" (Catches retroactive reconstruction early, before it becomes a habit.)
- "Walk me through one feedback instance in your log — what made it specific rather than vague, and how do you know the other person understood it?"
- "Do you have a cross-timezone async handoff note yet? If not, when's the next moment one will be needed?" (This is a P2 requirement from day one — don't let it slip to "later, once I'm client-facing.")
- "Is everything in your log so far with the same one or two people? If so, who's someone outside that circle you could build an instance with before the window closes?" (Catches a one-relationship bundle early.)
- "Has a disagreement come up yet? Walk me through it — and separately, has anything changed your mind about something real this week?" (Confirms these are being logged as two distinct things, not conflated.)
- "Is there anything about how feedback, communication, or collaboration works differently here than where you worked before — especially anything about the client relationship or the Nepal/India–US time gap — that still feels unclear?" (This question is for catching onboarding gaps, not testing the new hire — treat the answer as feedback on onboarding quality, not a mark against them.)
