# Strategic Impact — Badge Reference Card

**Purpose:** a one-screen lookup so a candidate or buddy can see, at a glance, which training unit prepares which badge — without re-reading all three assessment instruments. This card does not redefine anything; every cell links back to `../assessment/badges.md` and the instrument it names. If this card and an assessment instrument ever disagree, the instrument in `../assessment/` wins.

**Structural note:** this file follows the base shape established in Technical Skill's `training/05-badge-reference-card.md` — one row per badge, linking training unit → evidence artifact → instrument — but adds one column (**Exception path if blocked**) beyond that base 5-column shape, given this PF's exception-heavy evidence (§1.5–§1.8 routes apply to nearly every badge here). Everything else follows the established pattern; only the PF name, badge IDs, and artifact names are otherwise Strategic-Impact-specific.

---

## How to read this card

- **Badge ID** and **Name** — from `../assessment/badges.md` Part 2.
- **Training unit that builds it** — which guided exercise or autonomous project in this `training/` folder produces (or rehearses producing) the required evidence artifact.
- **Evidence artifact required** — restated from the badge's "Evidence required" field, so you know what to walk away from the training unit holding.
- **Exception path** — which `badges.md` §1.5–§1.8 mechanism applies if the standard evidence path is blocked (confidentiality, access-loss, no opportunity in the review period, permanently-siloed role).
- **Instrument** — which file in `../assessment/pf1-business-acumen-strategy/` actually awards the badge.

Training builds the artifact. It does not award the badge — only a Verifier at the role/level named in `../assessment/badges.md` Part 2 can do that (co-signed by the candidate's delivery/account manager at SI-1-P4 and SI-1-P6).

## What this card is not

- Not a substitute for reading the actual rubric/checklist/portfolio-requirements file before an assessment — it tells you where to look, not the full bar.
- Not a self-certification tool — see `../assessment/badges.md` §1.3 and §4 (Part 3): a badge requires the named Verifier's (and, at P4/P6, co-signer's) sign-off, always, and is recorded against the person's file or IDP, never inside the catalog or this card.
