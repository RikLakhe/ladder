# Delivery — Learning Path

Reads: `../functional-analysis.md`, `../standard/` (both PFs — read-only, not edited by this package), `../assessment/` (both PFs, including `badges.md` — the 12-badge catalog this training package is built to prepare candidates for, redesigned 2026-08-03), `../../industry-evidence/delivery.md`, `../../COMPANY-CONTEXT.md`.

**Level scope of this run:** whole P2–P7 ladder is covered structurally (both PFs run P2–P7 per `functional-analysis.md`), but the guided exercises and autonomous projects — the parts of this kit that are actually buildable as step-by-step content — are scoped to **P2–P5**, matching where the assessment package provides a concrete rubric/checklist target to train toward, not just a portfolio review. P6/P7 readiness is demonstrated through real cross-team/org-wide delivery work and portfolio review per each PF's Evidence Guide, not through guided exercises — see the Level gates section below and `03-autonomous-projects.md`'s framing. This is the same "P5–P7 growth is demonstrated through real scope, not guided exercises" principle the methodology names generally (see `competency-methodology.md`, "Level Scoping"), applied here rather than assumed.

See `05-badge-reference-card.md` for a one-screen map of every badge in `../assessment/badges.md` to the training unit that builds its evidence artifact.

**What changed in the 2026-08-03 assessment redesign, and why it reshapes this training package:**
- PF 1 P2/P3 evidence is no longer 2–3 best-case tickets — the rubric now requires **one coherent bundle of ≥5 real tickets from a single delivery unit** (a sprint, a small epic slice, or an engagement ramp period). Exercise 1 below is rebuilt around producing that bundle, not a single ticket.
- PF 2 P2–P4 evidence is no longer scattered status notes — the rubric now requires **one full, continuous 2–4 week delivery cycle's record**. Exercise 3 below is rebuilt as a sustained habit-tracking exercise with an explicit cycle boundary, not an open-ended ongoing task.
- Every guided exercise and autonomous project below now states which badge(s) it feeds and which instrument will actually score the resulting artifact — training builds the evidence; it does not award the badge (see `badges.md` §1.3).

## Prerequisites checklist

Before starting this learning path, confirm:

- [ ] Has taken on at least one real assigned task, so sizing/dependency exercises have a live reference point
- [ ] Access to the team's backlog/ticket tool and standup or async status channel, and knows how to pull a dated history from both (the redesigned rubrics check timestamps, not recollection)
- [ ] Has read `../../lft-engineering-competency-matrix.md` Section 2 "Delivery," so the P2–P7 language here isn't unfamiliar
- [ ] Has skimmed `../assessment/badges.md` Part 1 (the generic badge pattern) and Part 2's table for their target level, so they know what evidence they're accumulating from day one, not just what exercise they're doing
- [ ] Basic familiarity with Technical Skill PF 1 (Quality & Testing) or PF 3 (Software Design & Architecture) helps but isn't required — Delivery is about scoping and communicating work, not the technical work itself
- [ ] Knows which client engagement they're on, its contract type (fixed-bid vs T&M), and whether ceremonies/tooling/reporting cadence are set by the client or by the internal team — this changes how several exercises below should be read, and how the delivery-unit bundle and cycle record should be assembled
- [ ] Understands the **bundle**/**cycle** vocabulary before starting: a "delivery-unit bundle" (PF 1) is ≥5 tickets from one identifiable sprint/epic-slice/ramp period; a "cycle record" (PF 2) is one continuous 2–4 week span of status/escalation history. Neither can be assembled retroactively from memory — pick the unit/cycle *before* starting the exercises below so the record is real-time, not reconstructed.

## Level gates

- **P2 → P3:** the candidate's Exercise 1/2 bundle passes `pf1-incremental-value-delivery/01-work-product-review-rubric.md` at "Meets P3" across the whole bundle (≥5 tickets, one delivery unit), and the Exercise 3/4 cycle record passes `pf2-self-organization/01-work-product-review-rubric.md` at "Meets P3" across the full cycle. Badges typically cleared at this gate: DL-1-P3, DL-2-P3. Gate owner: manager, using the Phase D rubrics directly against the real bundle/cycle — not a summary of it.
- **P3 → P4:** passes `pf1.../02-live-demo-checklist.md` P4 scenario (Exercise 5 is rehearsal for this, not a substitute for it — the real scenario is proctored) and `pf2.../02-live-demo-checklist.md`'s P4 retrospective walkthrough (which requires manager/teammate corroboration of the cycle record, not just the candidate's account), and has shipped Autonomous Project 1 and 2 to the "good" quality bar. Badges typically cleared at this gate: DL-1-P4, DL-1-P4 requires a delivery/account-manager co-signer per `badges.md` §1.1 if any claimed client-scope-change context is part of the evidence — flag this early so the co-signer isn't a last-minute scramble.
- **P4 → P5:** scope-of-role transition (execution → facilitation) — not producible by a guided exercise. Gate is the Phase D portfolio requirements for P5 across both PFs (`pf1.../03-portfolio-requirements.md`, `pf2.../03-portfolio-requirements.md`), using real on-the-job evidence per each PF's Evidence Guide, plus the P5 live-demo/walkthrough scenario. Autonomous Project 3 is a reasonable on-ramp, not a substitute for the portfolio review.
- **P5 → P6 → P7:** same pattern, scaling scope from team to several teams to organization, with the §1.6 adoption-evidence artifact (named contact, dated reference, what changed) required for any P6/P7 badge whose Certifies line depends on adoption, and the §1.1 co-signer requirement applying again at Tier 5 (P6). See each PF's portfolio requirements — there is no further guided/autonomous content at this scale in this run; readiness is demonstrated through actual cross-team/org-wide delivery work, assessed via portfolio + (at P7) teaching demonstration.

## Levels built out this run vs. deferred

**Built out this run (P2–P5):** concept notes (unchanged in scope — theory doesn't level-gate), guided exercises (1, 2, 3, 4, 5) and autonomous projects (1, 2, 3) all target P2–P5 explicitly, rebuilt to produce the exact bundle/cycle artifacts the redesigned rubrics require, and each is labeled with the badge(s) it feeds.

**Deferred this run (P6–P7):** no new guided/autonomous content was built for P6/P7. This is a deliberate, stated deferral, not a silent gap — at P6/P7 both PFs' portfolio requirements call for real cross-team/org-wide work plus (at P7) a teaching demonstration, which by definition isn't something a guided exercise can simulate meaningfully. What P6/P7 candidates need from this training package is already present: the onboarding-track pattern, the concept notes (which don't level-gate), and the badge reference card's pointer to the correct portfolio-requirements file per PF. A future training run could add P6/P7-specific facilitation/mentoring guided content if the theme lead decides that's worth building despite the real-work bias — not done here.

## Skip guide

- **Experienced hire joining at P4 or above:** skip concept notes and guided exercises entirely. Start at Autonomous Project 1 or 2 (whichever matches their current assignment), and use the Phase D portfolio requirements to identify what evidence to bring from their prior role. Check `05-badge-reference-card.md` first to see which badges their existing bundle/cycle evidence might already satisfy.
- **Experienced hire joining at P3:** skim concept notes as a refresher, go straight to Exercises 2, 4, and 5 to confirm baseline, then proceed to the autonomous projects — but still assemble a real ≥5-ticket bundle and a real 2–4 week cycle record before claiming P3 badges; prior-role evidence in a different tracking system usually isn't in a reviewable format and needs to be rebuilt or re-exported.
- **Anyone with strong Shape Up / agile-planning background elsewhere:** skip Exercise 1's conceptual framing, but still produce the actual bundle — the badge doesn't care how familiar the candidate already is with splitting tasks, only whether ≥5 real, connected tickets show the pattern. Still do Exercise 2 (dependency mapping) and Exercise 5 (ambiguity under pressure) in full — LFT's specific escalation and cost/value habits (PF 2) are the part that doesn't transfer automatically from a prior planning framework.
- **Anyone who already has 2–4 weeks of clean, dated status history in the team's tool from real work (not from this training path):** Exercise 3/4 don't need to be run as a separate block — that existing history can stand in as the cycle record, provided it's continuous and undoctored. Confirm with the reviewing manager before assuming this substitution is accepted.
